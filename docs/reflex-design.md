# OmniJev 反射运行时实验设计

## 要检验的问题

在持续变化的物理世界中，现有全模态决策模型是否能承担局部反射判断：感知突发变化、及时改变运动、在条件消失后恢复任务。视觉大脑加入后，能否改善较慢的任务理解、目标更新及反射条件管理。

模型权重固定。反射由运行时的自然语言问题、候选动作和阈值定义，条件联结保存在可检索的经验记录中。元层可以更新 criteria 与阈值，全部版本和修改来源留痕。

## 两个主要实验组

| 组别 | 任务与目标更新 | 局部反射 |
|---|---|---|
| `omni` | 共享初始运动意图，OmniJev 根据当前观察选择局部修正 | OmniJev 反射银行、模型仲裁与阈值门控 |
| `vlm_omni` | g.92.run Gemini 3.8 Flash 低频看图规划，更新目标意图及反射条件 | 同一套 OmniJev 反射运行时 |

两组共享机器人、初始计划、物理参数、外界事件、感知接口和电机控制器。大脑输出任务级目标，OmniJev 输出下一次局部动作；相互独立的线程确保大脑思考时，小脑和世界继续运行。

## 时间尺度与感知边界

- MuJoCo 刚体物理为 500 Hz，经典关节/末端控制为 20 Hz。
- 相机目标频率 8 Hz，实际采集与渲染频率单独记录。
- 决策频率由真实接口吞吐决定，不把等待时间删掉；分别报告模型服务耗时、采集到命令的总年龄及失效保护。
- 模型可用输入为相机、机器人自身传感器、当前运动意图和检索经验。
- 人手/物体真实坐标、随机事件时间表、场景种子及评分标签仅用于环境生成和评价。
- 蓝色落点是初始意图或模型目标的相机投影，由固定标定计算，不跟踪目标真实位置。

## 反射运行时

反射银行用 `noul` 提供条件概率；`choice` 提供模型仲裁的动作候选；`score` 提供危险等级及其分布。为了控制调用延迟，当前实现让条件判断与动作候选共享同一帧、在一次批量调用中返回，然后由声明的概率阈值和仲裁置信度执行门控。模型候选不是读取本轮已返回概率后再生成的第二次推理，这一实现区别在报告中保留。

控制器只提供继续、刹停、有限距离退让、抬起、左右修正等有界运动原语。它不读取外界物体坐标来挑选反射。原语执行、关节限位和命令过期保护分别记录；软件保持不能算作模型反射。

经验记录联结观察特征、模型概率、实际动作和随后测得的机器人反馈。检索只提供过去的相似情况。元层接收真实相机、现有条件与这些反馈，输出受校验的条件/阈值更新；它不能修改控制器代码或执行任意工具。

## 外界与交互

连续世界包含具有惯性与接触力的人手和自由物体、移动目标、相机遮挡，以及随机顺序和间隔的组合事件。操作者可以随时注入干扰、修改反射条件、关闭/开启反射、重置或停止；这些操作改变环境或运行配置，不直接告诉模型该输出哪种动作。

固定场景用于核对机械与接口；成对随机场景用于比较两组。失败、无干扰时的动作、重复保持、延迟答复和物理接触均保存，不以剪辑或提前退让代替事件后反应。

## 判定与可证伪指标

1. 条件发生后，是否出现新鲜模型命令并真正改变运动；记录从事件开始与从观察采集计算的延迟。
2. 人手/物体接触峰值和冲量是否降低，同时任务是否能恢复或完成。
3. 无干扰区间的错误干预、漏反应、过期命令和 API 失败率。
4. 可定义标签的条件概率与实际情况是否一致；报告概率分箱、Brier/ECE，并说明时间样本相关性和小样本限制。
5. 加入大脑后的目标更新、条件更新是否实际应用，以及这些更新对结果的影响。
6. 结构化输出有效性与决策正确性分别测量。合法动作并不自动等于正确动作，校准概率也需要实测。

成对实验可以验证这套运行机制及当前模型在所测场景中的表现。有限场景不能单独证明通用条件反射理论，也不能把界面的“像小脑”当作神经机制等价。
